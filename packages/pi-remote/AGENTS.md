# pi-remote Packaging

- Keep the source revision and `npmDepsHash` in sync with the committed root lockfile. Pi remains a host-provided peer; use `--legacy-peer-deps` so npm never installs a second SDK.
- Build all workspaces, then install only the CLI's production dependency graph. The extension needs `extensions/`, the runtime/server/protocol sources, and `packages/web/dist` at their original relative paths; the hub and browser build tools are not runtime dependencies.
- The Pi module lists `${pi-remote}/lib/pi-remote` as a local package so the extension and command always use the same revision, and renders `~/.pi/agent/pi-remote.json` from the `pi_remote_endpoint` and `pi_remote_token` sops secrets. That token must equal the hub's SealedSecret, so rotate both together. It requires the `SESSION_BRIDGE_API_VERSION = 1` patch in `../pi-coding-agent`; extension and wrapper instance modes attach to stock Pi's interactive runtime without creating another session.
- Verify a real extension load, `/reload`, and `/new`; TypeScript does not catch loader identity or session-ownership failures. Run `packages/runtime/test/extension-smoke.mjs` with `PI_REMOTE_TEST_PI` set to the installed SDK's `packages/coding-agent`, `PI_REMOTE_TEST_PI_LAYOUT=dist`, and `PI_REMOTE_TEST_PACKAGE=<output>/lib/pi-remote`.
